# services/molecular/ — Full Molecular Testing Execution Module

Real feature, per a direct, detailed specification document ("PathScribe Full Molecular Testing Execution Module") — extends this app's existing sample-tracking/batching framework (`services/batches/`) to support Molecular Diagnostics workflows (HPV, CT/NG, Respiratory PCR panels, targeted NGS).

## Architecture decision, made before writing any code

Before building anything, the existing Histology batch system (`IBatchService.ts`, 393 lines) and hardware container registry (`IHardwareContainerRegistryService.ts`) were read directly. Real conclusion: this module reuses their established *patterns* — a master barcode representing one physical carrier, per-item audit fields, a closed lifecycle-status vocabulary — but is **not** folded into the existing `Batch`/`BatchItem` entities. A molecular plate's own spatial model (a 2D grid of wells, each holding a real control or a real patient specimen at a specific row/column coordinate) has no analog in the existing `BatchItem` shape (a flat list of scanned items, no spatial concept at all). Forcing the two together would have distorted a working, real system for Histology to accommodate a genuinely different geometry.

## Phase 7 (Sep 2026) — a real, mathematically-verified ZPL layout for the multi-zone requisition sheet
