# services/terminologySearch/

Live REST API client for clinical terminology search — SNOMED CT, ICD-10, ICD-11, LOINC, ICD-O, OPCS-4, CPT — against NLM Clinical Tables and UTS endpoints.

**Pattern:** Not the interface/mock/firestore triplet pattern — this is a real, direct external API integration, no mock/dictionary aspect.

## Files

- **`codeSearchService.ts`** — Relocated here July 2026 from pages/Synoptic/Codes/ — genuinely different concern from services/codes/ (which is config/dictionary only). SECURITY FIX also applied July 2026: removed a hardcoded UMLS API key fallback that had been committed to source; now throws loudly via getUmlsApiKey() if VITE_UMLS_KEY isn't set in the environment.
- **`verifyCodeExists()` / `filterToVerifiedCodes()`** — real, per direct guidance: "before any suggestion is [shown, verify] that code actually exists and is a real code. Machine verified. Then the Practitioner makes the medical decision to use or not use that code." Applies to every real system this app's Code Manager (`pages/Synoptic/Codes/AddCodeModal.tsx`) presents from its AI-suggestion panel — SNOMED, ICD-10, ICD-11, ICD-O, LOINC. Deliberately reuses this file's own already-working, already-tested search functions (searching by the AI's own claimed display text, then checking for a real result with an EXACT matching code) rather than a new, separate "exact code lookup" query shape this code can't empirically verify against the real, live UTS/NLM endpoints from this environment. Fails closed on any real error — an unverifiable code is never assumed real. CPT is deliberately short-circuited to trusted here, since it already has its own, separate, pre-existing re-verification against the real, curated `CODE_MAP_TABLE` inside `AddCodeModal.tsx` itself — never checked twice. **9 real tests**, including the exact real-world case this exists to catch (a code the AI claims that never appears in the real, live search results).
  - **Real, per direct follow-up on performance**: "we want the Pathologist to get the answer, we just need to optimize our code and approach to make sure PathScribe is not the performance problem." A timeout is a real, necessary safety net against a genuinely dead connection (`TERMINOLOGY_SEARCH_TIMEOUT_MS`, 5s, shared `fetchWithTimeout()` wrapping every real `fetch()` in this file) — but it is deliberately NOT treated as the performance answer, since it fails a slow-but-working call faster rather than making it resolve faster. The real optimization is `verifyCodeExists`'s own in-memory cache: a positive result is cached by `(system, code)` alone, since existence doesn't depend on which search phrase found it — but a negative result is scoped to the exact `(system, code, displayHint)` query, and a network/timeout failure is never cached at all, since either could otherwise silently hide a real, valid code from a pathologist behind one bad query or one transient outage. **7 more tests** cover the cache's own real behavior and both of these deliberate safety asymmetries.

## Notes

- Several code systems (OPCS-4) are explicitly stubbed pending a licensed backend proxy — NLM doesn't host these (OPCS-4 needs NHS TRUD licence). **CPT is no longer one of them** — real fix, from a direct product question about a real, missing CPT-code-management UI: `searchCpt()` was a permanent, documented "not yet implemented" stub (genuinely correct reasoning at the time — NLM doesn't have CPT, AMA copyright restricts a full database) that had silently returned an empty array forever. It now searches the app's own, small, manually-curated, verified `Code_Map_Table` (`services/billing/codeMapTable.ts`) instead — not a substitute for full CPT coverage (still not available without a licensed backend), but real, legally clean data for the handful of codes this app actually tracks. Real consumer: `pages/Synoptic/Codes/AddCodeModal.tsx`'s CPT tab, which already had a fully-built UI (tabs, search, apply/undo) wired to this permanently-empty stub — also needed `MedicalCode.system` (`pages/Synoptic/synopticTypes.ts`) widened from `'SNOMED' | 'ICD'` to include `'CPT'`, and `SynopticReportPage.tsx`'s save/load callbacks fixed to actually handle the `'CPT'` case (previously any CPT code selected in this modal would have been silently dropped on save — never checked, never written to `Case.coding.cpt`).
- **Real, current key-handling posture:** `searchSnomed`/`searchIcdo` route through a real, server-side Vite proxy (`vite.config.ts`'s own `/api/terminology/umls` route), which injects the real UMLS API key server-side from `env.UMLS_API_KEY` — never a `VITE_`-prefixed variable, so it's never bundled into client-side JS at all. A real, live gap this surfaced while investigating: `components/Config/Terminology/terminologyConfig.ts`'s own `testTerminologyEndpoints()` health check was calling `uts-ws.nlm.nih.gov` directly with a real API key hardcoded in the URL, bypassing this proxy entirely — a genuine, client-side-exposed credential, live every time `TerminologyServicesSection.tsx` ran its health check. **Now fixed** — see that folder's own README for the full account, including a second, related bug (wrong response-shape parsing) fixed alongside it.
